Environments

The environment

Kraken.UnderwaterEnv — Type
UnderwaterEnv{T1,T2,T3,T4,TB,BB}

A range-independent underwater environment: the sound speed, density and attenuation profiles of the water column and sediment layers, the bottom half-space, the layer interfaces, and the two boundary conditions. Build one with UnderwaterEnv(ssp, layers, sspHS; ...); the fields below are what the solver reads.

Fields

  • c, ρ, α: the SampledSSP, SampledDensity and SampledAttenuation profiles of the whole column.
  • cb, ρb, αb: sound speed (m/s), density (kg/m³) and attenuation of the bottom half-space.
  • h_vec, layer_depth: each medium's thickness and the depth of its lower interface (m).
  • depth: the depth of the last interface, where the bottom boundary sits.
  • atten_units: the units of α and αb, one of the values of ATTENUATION_UNIT_CHARS.
  • top_bc, bottom_bc: the BoundaryConditions.

α and αb are the water-column and half-space attenuations in the units named by atten_units; nothing converts them until a frequency is known. An environment whose attenuations are all zero is lossless and kraken_jl then returns real wavenumbers, exactly as it did before attenuation existed — see is_lossy.

top_bc and bottom_bc are the BoundaryConditions closing the problem above the water column and below the last medium.

source

UnderwaterEnvFORTRAN{T}

The three KRAKEN .env-style matrices of an environment, ssp, layers and sspHS, stored as they are rather than interpreted. UnderwaterEnv has a constructor that takes one.

Kraken.is_lossy — Function
is_lossy(env::UnderwaterEnv) -> Bool

Whether env declares any attenuation at all, in the water column or in the bottom half-space.

This is the switch that decides whether kraken_jl returns complex wavenumbers or real ones. It is deliberately a test on the stored values rather than on the converted ones: Q = 0 converts to zero nepers/m and α = 0 does too, so both spellings of "lossless" take the same branch.

Under AD this is a discrete decision on a parameter value, in the same family as the mesh-schedule choice in kraken_jl, and α = 0 is a genuine kink: imag(kr) is identically zero below it and linear above. The two AD modes therefore take opposite sides there and neither complains — ForwardDiff's iszero on a Dual sees the seed and takes the lossy branch (right-hand derivative), while Zygote evaluates this on the primal and takes the lossless one (zero). Differentiate at a nonzero attenuation. See the note at the end of src/kraken_ad.jl.

Example

julia> is_lossy(UnderwaterEnv(pekeris_env()...)), is_lossy(UnderwaterEnv(pekeris_env(; αb=0.5)...))
(false, true)

Profiles

Depths are in metres, positive downwards from the surface.

Kraken.SampledSSP — Type
SampledSSP(depth, c)
SampledSSP(depth, c, mode::Symbol)

Create a sound speed profile from measurements at discrete depths depth in meters (positive downwards, from the surface) and sound speeds c in m/s. Query it with soundspeed.

mode is one of :c_linear (the default — c linear in depth), :n2_linear (1/c² linear in depth) or :cubic_spline. All three agree at the sample depths and differ between them.

:cubic_spline requires strictly increasing depths, so it is limited to a single medium: this package spells a layer interface as two samples at (numerically) the same depth, and one spline through the whole column would be wildly wrong there rather than merely inexact. KRAKEN splines each medium separately; doing the same here needs a per-medium profile this type does not have yet.

Example

julia> ssp = SampledSSP([0.0, 100.0], [1500.0, 1520.0]);

julia> soundspeed(ssp, 50.0)
1510.0

julia> round(soundspeed(SampledSSP([0.0, 100.0], [1500.0, 1520.0], :n2_linear), 50.0); digits=4)
1509.9007
source
Kraken.SampledDensity — Type
SampledDensity(depth, ρ)

Create a density profile from measurements at discrete depths depth in meters (positive downwards) and densities ρ in kg/m³. Interpolation between samples is linear. Query it with density.

Example

julia> ρ = SampledDensity([0.0, 100.0], [1000.0, 1100.0]);

julia> density(ρ, 25.0)
1025.0
source
Kraken.SampledAttenuation — Type
SampledAttenuation(depth, α)

Create an attenuation profile from values α sampled at discrete depths depth in meters (positive downwards). α is in whatever units the enclosing UnderwaterEnv declares as atten_units. Interpolation is linear, to match SampledSSP and SampledDensity — the three profiles are evaluated on the same mesh and a different interpolator here would put the attenuation somewhere the sound speed is not. Query it with attenuation.

Example

julia> α = SampledAttenuation([0.0, 100.0], [0.0, 0.2]);

julia> attenuation(α, 50.0)
0.1
source
Kraken.soundspeed — Function
soundspeed(ssp::SampledSSP, z)

Get the sound speed (m/s) at depth z (m), interpolated as the profile's mode says. z may be a number or a vector of depths.

Depths are positive downwards from the surface, the same convention as the ssp table an UnderwaterEnv is built from. A negative depth is not an error: it lies above the first sample, and the profile extrapolates as a constant, so it silently returns the surface value.

Example

julia> env = UnderwaterEnv(munk_env()...);

julia> soundspeed(env.c, 1300.0)   # the sound-channel axis
1500.0

julia> soundspeed(env.c, -1300.0) == soundspeed(env.c, 0.0)
true
source

density(ρ::SampledDensity, z)

Get the density (kg/m³) at depth z (m, positive downwards). z may be a number or a vector. The depth convention, and the constant extrapolation outside the table, are as for soundspeed.

At a layer interface the value is the one from the medium above.

Kraken.attenuation — Function
attenuation(α::AttenuationProfile, z)

Get the attenuation at depth z (m, positive downwards), in the profile's own declared units. z may be a number or a vector of depths. The depth convention is the same as soundspeed's, and so is the warning there about negative depths.

Boundary conditions

Kraken.BoundaryCondition — Type
BoundaryCondition

Supertype of the conditions that close the depth-separated problem at the top of the water column and at the bottom of the last medium. They correspond to KRAKEN's boundary-option characters: PressureRelease is V, RigidBoundary is R, AcousticHalfspace is A.

The types are tags and carry no data. A half-space's properties stay on the environment (cb, ρb, αb for the bottom), which is where the reverse-mode rules and the Mooncake bridge read them. Pass them to UnderwaterEnv as its top_bc and bottom_bc keywords.

Example

julia> all(bc -> bc isa BoundaryCondition, (PressureRelease(), RigidBoundary(), AcousticHalfspace()))
true
source
Kraken.PressureRelease — Type
PressureRelease()

A vacuum beyond the boundary, so the pressure vanishes on it: KRAKEN's V option. This is the default top boundary of an UnderwaterEnv, the free sea surface. It may also close the bottom, in which case the half-space row of sspHS is ignored.

Example

julia> env = UnderwaterEnv(pekeris_env()...; bottom_bc=PressureRelease());

julia> env.top_bc, env.bottom_bc
(PressureRelease(), PressureRelease())
source
Kraken.RigidBoundary — Type
RigidBoundary()

A perfectly rigid boundary, so the normal particle velocity (and with it ∂ψ/∂z) vanishes on it: KRAKEN's R option. Allowed at the top or the bottom.

Example

julia> env = UnderwaterEnv(pekeris_env()...; bottom_bc=RigidBoundary());

julia> sol = kraken_jl(env, 50.0);

julia> length(sol.kr)
7
source
Kraken.AcousticHalfspace — Type
AcousticHalfspace()

A homogeneous fluid half-space beyond the boundary: KRAKEN's A option. This is the default bottom boundary of an UnderwaterEnv, whose half-space sound speed, density and attenuation are its cb, ρb and αb.

Supported at the bottom only. Above the surface it describes no modal problem — see assert_supported_boundaries.

Example

julia> UnderwaterEnv(pekeris_env()...).bottom_bc
AcousticHalfspace()

Attenuation units

Kraken.attenuation_nepers_per_m — Function
attenuation_nepers_per_m(α, c, freq, units::Symbol)

Convert an attenuation α given in units into nepers per metre, at sound speed c (m/s) and frequency freq (Hz).

units is one of :nepers_per_m, :dB_per_m, :dB_per_kmHz, :dB_per_wavelength, :Q, :loss_parameter — the six conventions CRCI implements, keyed off TopOpt(3:3) (see ATTENUATION_UNIT_CHARS).

symbolcharmeaningconversion
:nepers_per_mNnepers/mα
:dB_per_mMdB/mα / 8.6858896
:dB_per_kmHzFdB/(m·kHz), i.e. dB/(km·Hz)α · freq / 8685.8896
:dB_per_wavelengthWdB/wavelengthα · freq / (8.6858896 · c)
:QQquality factorω / (2 c α)
:loss_parameterLloss parameterα · ω / c

Four of the six depend on frequency, which is why an environment stores the raw values and this conversion happens inside the solve. The degenerate guards (c == 0, c·α == 0) are KRAKEN's own and return zero rather than a division by zero — Q = 0 in particular is how a lossless medium is spelled under that convention, so it has to mean "no loss" and not Inf.

Example

julia> attenuation_nepers_per_m(8.6858896, 1500.0, 100.0, :dB_per_m)   # 8.686 dB = 1 neper
1.0

julia> attenuation_nepers_per_m(0.0, 1500.0, 100.0, :Q)                # Q = 0 means lossless
0.0
source
Kraken.ATTENUATION_UNIT_CHARS — Constant
ATTENUATION_UNIT_CHARS::Dict{Char,Symbol}

Map from the attenuation-unit character in a KRAKEN top-option string (TopOpt(3:3)) to the symbol attenuation_nepers_per_m accepts. Two are easy to misread: 'M' is dB per metre, not dB/km, and 'F' is dB/(m·kHz), the same quantity as dB/(km·Hz).

Example

julia> ATTENUATION_UNIT_CHARS['M']
:dB_per_m

julia> env = UnderwaterEnv(pekeris_env(; αb=0.1)...; atten_units=ATTENUATION_UNIT_CHARS['M']);

julia> env.atten_units
:dB_per_m
source
Kraken.DEFAULT_ATTENUATION_UNITS — Constant
DEFAULT_ATTENUATION_UNITS::Symbol

The default attenuation units: :dB_per_wavelength, KRAKEN's 'W'.

This is KRAKEN's most common choice and the one the test-only .env writer (DEFAULT_TOPOPT) already emitted while every αp was zero, so it is the value that keeps existing environments reading exactly as they did.

Example

julia> UnderwaterEnv(pekeris_env(; αb=0.5)...).atten_units === DEFAULT_ATTENUATION_UNITS
true

Standard environments

Each returns the (ssp, layers, sspHS) triple that UnderwaterEnv takes.

Kraken.munk_env — Method
munk_env()

Munk canonical deep-water sound-speed profile, 5000 m of water over a fluid half-space.

Returns (ssp, layers, sspHS), sampled every 100 m. The profile is

\[c(z) = 1500 \, [1 + ε (ẑ - 1 + e^{-ẑ})], \quad ẑ = 2(z - 1300)/1300, \quad ε = 0.00737\]

so its minimum is exactly 1500.0 m/s at the 1300 m sound channel axis, where ẑ = 0. That value and location are the defining property of the profile — the environment tests assert both.

It takes no arguments.

Example

julia> env = UnderwaterEnv(munk_env()...);

julia> env.depth, soundspeed(env.c, 1300.0)
(5000.0, 1500.0)
source
Kraken.one_layer_env — Method
one_layer_env(; c0=1500.0, c1=1550.0, cb=1600.0, ρ0=1000.0, ρ1=1500.0, ρb=2000.0, h0=100.0, h1=20.0, α0=0.0, α1=0.0, αb=0.0)

Water column over one isovelocity sediment layer over a fluid half-space.

Returns (ssp, layers, sspHS). h0 is the water depth, h1 the sediment thickness; c1/ρ1 are the sediment properties. The multi-medium case that exercises the interface conditions in AcousticProblemCache.

α0, α1 and αb are the compressional attenuations of the water, the sediment and the half-space, in the units the UnderwaterEnv declares (dB/wavelength unless atten_units says otherwise). All default to zero. A lossy sediment layer is the physically common case and the one this environment exists for: α1 enters through the volume integral rather than the half-space term, so it has none of the bottom-cutoff blow-up that a large αb suffers.

α1 makes the integrand discontinuous at the top of the sediment, which is why modal_attenuation and normalize_mode integrate medium by medium rather than with one trapezoid over the whole mesh — a single straddled interval there is enough to cost an order of convergence. With that, α1 = 0.4 dB/λ agrees with kraken.exe to 2.9e-3 at the default mesh and converges at second order; a flat trapezoid gave 8.1e-2 and first order.

Arguments

  • c0, ρ0, h0, α0: water sound speed (m/s), density (kg/m³), depth (m) and attenuation.
  • c1, ρ1, h1, α1: the same for the sediment layer, h1 being its thickness.
  • cb, ρb, αb: the half-space's sound speed, density and attenuation.

Example

julia> env = UnderwaterEnv(one_layer_env()...);

julia> env.layer_depth, env.h_vec
([100.0, 120.0], [100.0, 20.0])
source

one_layer_slope_env(; c0=1500.0, c1_1=1550.0, c1_2=1580.0, cb=1600.0, ρ0=1000.0, ρ1=1500.0, ρb=2000.0, h0=100.0, h1=20.0)

Kraken.pekeris_env — Method
pekeris_env(; c0=1500.0, cb=1600.0, ρ0=1000.0, ρb=1500.0, depth=100.0, α0=0.0, αb=0.0)

Canonical Pekeris waveguide: one isovelocity water layer over a homogeneous fluid half-space.

Returns (ssp, layers, sspHS) in the KRAKEN .env record layout, ready for UnderwaterEnv. ssp columns are [z, cp, cs, ρ, αp, αs].

This is the environment with a closed-form solution — see PekerisUnderwaterEnv and find_kr(::PekerisUnderwaterEnv, freq) — which makes it the reference for checking the finite-difference solver. Note that the closed-form solution is lossless: give this environment an attenuation and only the finite-difference path models it.

Arguments

  • c0, ρ0: water column sound speed (m/s) and density (kg/m³).
  • cb, ρb: bottom half-space sound speed and density. cb must exceed c0 for trapped modes.
  • depth: water depth (m), i.e. the interface with the half-space.
  • α0, αb: compressional attenuation in the water column and the half-space. Units are the environment's, not this function's — UnderwaterEnv defaults to dB/wavelength and takes an atten_units keyword. Both default to zero, which leaves the waveguide lossless and every wavenumber real.

Attenuation

lossy = UnderwaterEnv(pekeris_env(; αb=0.5)...)          # 0.5 dB per wavelength in the seabed
nepers = UnderwaterEnv(pekeris_env(; α0=1e-3)...; atten_units=:nepers_per_m)
kraken_jl(lossy, 100.0).kr                                # ComplexF64; Im(kᵣ) < 0

Prefer α0 (water-column loss) when the accuracy of the attenuation matters: the half-space term of the perturbation carries a 1/γ that grows without bound at the bottom cutoff, so a large αb degrades the least-trapped mode first. See modal_attenuation.

Example

julia> ssp, layers, sspHS = pekeris_env(; depth=200.0);

julia> size(ssp), layers
((2, 6), [0.0 0.0 200.0])

julia> kraken_jl(UnderwaterEnv(pekeris_env()...), 100.0)
NormalModeSolution{Float64}(5 modes)
source

two_layer_slope_env(; c0=1500.0, c1_1=1550.0, c1_2=1580.0, c2_1=1600.0, c2_2=1650.0, cb=1800.0, ρ0=1000.0, ρ1=1500.0, ρ2=1600.0, ρb=2000.0, h0=100.0, h1=20.0, h2=20.0)

Water column over two sediment layers, each with a linear sound-speed gradient, over a fluid half-space.
