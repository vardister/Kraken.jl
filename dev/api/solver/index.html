Solver

Solving

Kraken.kraken_jl — Function
kraken_jl(env, freq; n_meshes=5, rmax=10_000, method=ITP(), dont_break=false, abstol=1e-6, reltol=1e-6)

Solve the normal-mode problem for environment env at frequency freq (Hz). Top-level entry point.

Discretizes the depth-separated wave equation on a sequence of successively finer meshes, brackets each mode with bisection, refines it with solve_for_kr, recovers the mode shapes with inverse_iteration, and Richardson-extrapolates the squared wavenumbers across mesh levels until they converge.

Returns a NormalModeSolution with fields kr (horizontal wavenumbers, descending), modes (one column per mode, sampled on the first and coarsest mesh, which is props), env, and props. Returns an empty solution when the environment supports no trapped modes at this frequency.

Keyword arguments

  • n_meshes: maximum number of mesh refinement levels to extrapolate across.
  • rmax: maximum range of interest (m). Sets the convergence criterion: refinement stops once the wavenumber change would shift phase by less than one radian over rmax.
  • method: bracketing solver passed to IntervalNonlinearProblem.
  • dont_break: run all n_meshes levels even after convergence. Useful for studying mesh error.
  • abstol, reltol: tolerances forwarded to the root solver.

Differentiability

kraken_jl is differentiable end to end in both directions: forward mode straight through, reverse mode via the rules in kraken_ad.jl. Two properties of the returned gradient are structural, and no tolerance setting changes them:

  • It is conditional on the mesh schedule this call selected. The number of refinement levels is chosen by the convergence test above, which is an integer decision in the parameters; it is wrapped in ignore_derivatives so the gradient is taken at fixed schedule. That is the standard treatment, but it makes the gradient discontinuous at parameter values where the level count changes. Approach such a point from either side and the two one-sided gradients differ by the extrapolation's own error term. Pass dont_break=true for a schedule that is fixed by construction if a smooth objective matters more than the cost.
  • The mode shapes come from the coarsest mesh, as they do in the primal; only the wavenumbers are extrapolated. So ∂modes/∂θ is the derivative of the level-1 solve.

Arguments

  • env: the UnderwaterEnv to solve.
  • freq: frequency (Hz).

Example

julia> env = UnderwaterEnv(pekeris_env()...);

julia> sol = kraken_jl(env, 100.0)
NormalModeSolution{Float64}(5 modes)

julia> round.(sol.kr; digits=4)
5-element Vector{Float64}:
 0.4179
 0.415
 0.41
 0.4029
 0.3938

julia> kraken_jl(UnderwaterEnv(pekeris_env(; αb=0.5)...), 100.0)   # lossy: complex kᵣ
NormalModeSolution{ComplexF64}(5 modes)

The finite-difference pipeline

What kraken_jl does on each mesh, in order. Call these directly only to work on a single mesh, or to study one step.

Kraken.AcousticProblemProperties — Type
AcousticProblemProperties{T,T2}

The finite-difference mesh for one environment at one frequency: step 2 of the solve, between the environment and the AcousticProblemCache. kraken_jl builds these itself; you need one only to drive the lower-level functions (bisection, find_kr, inverse_iteration, …) by hand.

Fields

  • freq: frequency (Hz).
  • Nz_vec: mesh points in each medium.
  • Δz_vec: mesh spacing in each medium (m).
  • zn_vec: each medium's mesh depths (m, positive downwards).
source
Kraken.AcousticProblemCache — Type
AcousticProblemCache{T}

The assembled finite-difference system for one mesh: step 3 of the solve. Root finding and inverse iteration evaluate the system at many trial wavenumbers, and the cache is what they reuse and mutate in place, restoring it before they return.

Fields

  • a_vec: main diagonal, which A shares rather than copies.
  • e_vec: off-diagonals.
  • λ_scaling: the factor multiplying kr² on each row.
  • A: the Tridiagonal matrix over a_vec and e_vec.

See finite_difference_coefficients for what each vector holds.

source
Kraken.finite_difference_coefficients — Function
finite_difference_coefficients(env::UnderwaterEnv, props::AcousticProblemProperties)

Assemble the finite-difference coefficients for env on the mesh described by props. Returns (a_vec, e_vec, λ_scaling), the three vectors AcousticProblemCache stores.

This is the whole dependence of the discretized problem on the environment parameters, isolated as a pure function: it allocates its results and mutates nothing, neither its arguments, nor a cache, nor a locally allocated buffer. That is what puts it on the differentiable seam (see the note at the top of this file). Reverse-mode AD traces this function, so keep it free of setindex!, push!, and in-place broadcasts; the mutating hot path lives behind the rules in create_finite_diff_matrix! and never needs to be traced.

  • a_vec: main diagonal, from a_element; at each interface between two media the value is the average of the coefficients on either side.
  • e_vec: off-diagonals, from e_element.
  • λ_scaling: the factor multiplying kr² in the Sturm sequence: a two-point moving average of e_vec * Δz², with the final entry halved when the bottom is a mesh point (a half-space or rigid bottom) and the first entry halved, along with a_vec[1], for a rigid surface.

The mesh (Nz_vec, Δz_vec, zn_vec) is piecewise constant in the parameters and is treated as a constant here; only env carries derivative information.

Example

julia> env = UnderwaterEnv(one_layer_env()...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> a, e, λ = finite_difference_coefficients(env, props);

julia> length(a) == length(e) == length(λ) == sum(props.Nz_vec)
true

Kraken.get_g — Function
get_g(kr, env::UnderwaterEnv, props::AcousticProblemProperties)

Get the value of g for the bottom half-space finite-difference element: √(kr² - (ω/cb)²) / ρb, or zero when the bottom is a RigidBoundary or PressureRelease and there is no half-space.

With a half-space, only defined for kr >= 2π * freq / cb, i.e. for modes that are evanescent in the bottom half-space. Below that cutoff the vertical wavenumber in the bottom is real (a radiating, leaky mode) and this real-valued formulation has no solution. bisection therefore only ever searches kr ∈ [ω/cb, max(ω/c)]; calling get_g (or det_sturm) below the cutoff throws a DomainError from sqrt.

Arguments

  • kr: trial horizontal wavenumber (1/m).
  • env: the environment; cb, ρb and bottom_bc are read.
  • props: the problem properties, for the frequency.

Example

julia> env = UnderwaterEnv(pekeris_env()...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> kr = 2π * 100 / 1550;   # between ω/cb and ω/c

julia> round(get_g(kr, env, props); sigdigits=4)
6.703e-5
source
Kraken.det_sturm — Function
det_sturm(kr, env::UnderwaterEnv, props::AcousticProblemProperties, cache::AcousticProblemCache; scale=true)

Evaluate the Sturm sequence of the finite-difference system at trial wavenumber kr.

Returns (det, mode_num): the determinant of the tridiagonal system, and the number of modes with wavenumber above kr (the count decreases as kr sweeps up through the trapped band). scale=true rescales the sequence whenever it would overflow or underflow; the factor is piecewise constant in both kr and the environment parameters, so it cancels in any derivative of the root and does not affect the mode count.

With a half-space bottom, only defined for kr >= 2π * freq / cb; see get_g.

Arguments

  • kr: trial horizontal wavenumber (1/m).
  • env, props, cache: the environment, its mesh, and the system assembled on it.

Example

The Pekeris waveguide at 100 Hz has 5 modes, and 2 of them lie above kr = 0.41:

julia> env = UnderwaterEnv(pekeris_env()...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> cache = AcousticProblemCache(env, props);

julia> det_sturm(0.41, env, props, cache).mode_num
2
source
Kraken.bisection — Function
bisection(env::UnderwaterEnv, props::AcousticProblemProperties, cache::AcousticProblemCache)

Bisection method to find the intervals where the roots (wavenumbers) lie.

Searches kr ∈ [ω/(0.9999 cb), max(ω/c)], the band in which modes are trapped, or down to kr = 0 when the bottom is rigid or vacuum and nothing can leak out of the column. Returns an n_modes × 2 matrix of [left right] brackets, or nothing when the environment supports no trapped modes at this frequency (e.g. water too shallow relative to the wavelength).

Each bracket holds exactly one root of det_sturm, which is what solve_for_kr needs. Mode counting is by the Sturm sequence, so no root is missed however closely two modes are spaced.

Arguments

  • env, props, cache: the environment, its mesh, and the system assembled on it.

Example

julia> env = UnderwaterEnv(pekeris_env()...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> size(bisection(env, props, AcousticProblemCache(env, props)))
(5, 2)

julia> props5 = AcousticProblemProperties(env, 5.0);   # below the first mode's cutoff

julia> bisection(env, props5, AcousticProblemCache(env, props5)) === nothing
true
source
Kraken.find_kr — Method
find_kr(env::UnderwaterEnv, props::AcousticProblemProperties, cache::AcousticProblemCache; method=ITP(), kwargs...)

Find every trapped-mode wavenumber of the finite-difference system on one mesh, in descending order: bisection brackets them and solve_for_kr refines each bracket. Returns an empty vector when there are no trapped modes.

These are single-mesh wavenumbers, carrying the mesh's discretization error. kraken_jl calls this on several meshes and extrapolates.

Arguments

  • env, props, cache: the environment, its mesh, and the system assembled on it.
  • method: any bracketing solver from NonlinearSolve.jl accepted by IntervalNonlinearProblem.
  • kwargs...: passed to solve, e.g. abstol and reltol.

For the closed-form Pekeris model, see find_kr(::PekerisUnderwaterEnv, freq).

Example

julia> env = UnderwaterEnv(pekeris_env()...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> round.(find_kr(env, props, AcousticProblemCache(env, props)); digits=4)
5-element Vector{Float64}:
 0.4179
 0.415
 0.41
 0.4029
 0.3938
source
Kraken.solve_for_kr — Function
solve_for_kr(span, env, props, cache; method=ITP(), kwargs...)

Refine one mode's wavenumber: the root of det_sturm inside the bracket span.

Arguments

  • span: a two-element [left, right] bracket containing exactly one root, i.e. one row of bisection's result.
  • env, props, cache: the environment, its mesh, and the system assembled on it.
  • method: a bracketing solver accepted by IntervalNonlinearProblem.
  • kwargs...: passed to solve.

This is one of the two functions carrying a reverse-mode rule: its derivative comes from the implicit function theorem applied to det_sturm, not from differentiating the solver's iterations.

Example

julia> env = UnderwaterEnv(pekeris_env()...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> cache = AcousticProblemCache(env, props);

julia> spans = bisection(env, props, cache);

julia> round(solve_for_kr(spans[1, :], env, props, cache); digits=4)
0.4179
source
Kraken.inverse_iteration — Function
inverse_iteration(kr, env::UnderwaterEnv, props::AcousticProblemProperties, cache::AcousticProblemCache; reltol=0.01)
inverse_iteration(kr_vec::Vector, env, props, cache; reltol=0.01)

Recover the normalized mode shape ψₘ belonging to the wavenumber kr: step 5 of the solve.

Returns (kr_new, ψ), the iteration's refined wavenumber and the mode sampled on the flattened mesh reduce(vcat, props.zn_vec), normalized so that its energy is one. Given a vector of wavenumbers it returns a vector and a matrix with one mode per column.

Composed of mode_eigenvector, which is opaque to reverse-mode AD and carries its own rule, and normalize_mode, which is traced.

Arguments

  • kr / kr_vec: converged wavenumbers, e.g. from find_kr.
  • env, props, cache: the environment, its mesh, and the system assembled on it.
  • reltol: passed to mode_eigenvector.

Example

julia> env = UnderwaterEnv(pekeris_env()...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> cache = AcousticProblemCache(env, props);

julia> krs, modes = inverse_iteration(find_kr(env, props, cache), env, props, cache);

julia> size(modes)
(125, 5)
source
Kraken.mode_eigenvector — Function
mode_eigenvector(kr, env::UnderwaterEnv, props::AcousticProblemProperties, cache::AcousticProblemCache; reltol=0.01)

Inverse-iterate the finite-difference system at wavenumber kr for the mode shape it supports.

Returns (kr_new, v): the refined wavenumber estimate produced by the iteration, and the eigenvector, scaled to ‖v‖₂ = 1 and sign-fixed so that v[1] ≥ 0. Physical normalization is normalize_mode's job.

This is the second of the two functions behind the differentiable seam (see the note at the top of this file): it mutates the cache, branches on argmax, and iterates, and reverse mode never traces any of it; src/kraken_ad.jl states the eigenvector adjoint directly instead. The cache is left exactly as it was found.

Arguments

  • kr: a converged wavenumber, e.g. from find_kr. The iteration shifts slightly below it.
  • env, props, cache: the environment, its mesh, and the system assembled on it.
  • reltol: stop once successive iterates differ by less than this, relatively (1%).

Example

julia> env = UnderwaterEnv(pekeris_env()...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> cache = AcousticProblemCache(env, props);

julia> kr = first(find_kr(env, props, cache));

julia> kr_new, v = mode_eigenvector(kr, env, props, cache);

julia> length(v) == sum(props.Nz_vec), v[1] >= 0
(true, true)
source
Kraken.normalize_mode — Function
normalize_mode(v, kr, env::UnderwaterEnv, props::AcousticProblemProperties)

Scale a mode shape so that its total energy, water column plus bottom half-space, is one:

∫ v(z)² / ρ(z) dz  +  v(D)² / (2 ρb √(kr² - (ω/cb)²))  =  1

v is mode_eigenvector's unit-2-norm eigenvector; the scaling is what turns it into the mode function the field sum expects. With a rigid or vacuum bottom there is no half-space and the second term is zero.

Kept on the differentiable seam on purpose. The normalization is the only part of a mode shape that depends on the density profile and the mesh coordinates other than through the finite-difference coefficients, and leaving it traced means the backend reaches env.ρ through the same density call it already differentiates in finite_difference_coefficients, rather than the eigenvector rule having to carry an interpolant adjoint of its own.

Arguments

  • v: the eigenvector, sampled on the flattened mesh reduce(vcat, props.zn_vec).
  • kr: its wavenumber, which sets the half-space decay rate.
  • env, props: the environment and its mesh.

Example

julia> env = UnderwaterEnv(pekeris_env()...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> cache = AcousticProblemCache(env, props);

julia> kr0 = first(find_kr(env, props, cache));

julia> kr, v = mode_eigenvector(kr0, env, props, cache);

julia> ψ = normalize_mode(v, kr, env, props);   # exactly what inverse_iteration returns

julia> ψ == last(inverse_iteration(kr0, env, props, cache))
true

Attenuation

Kraken.add_attenuation — Function
add_attenuation(krs, modes, env, props)

Turn converged real wavenumbers into complex ones by adding the first-order attenuation perturbation of modal_attenuation to each kᵣ².

Returns krs unchanged, and still real, when env declares no attenuation. The is_lossy guard exists for this, instead of adding a zero: a lossless environment goes through the same arithmetic it always did and every existing result stays bit-identical, instead of acquiring a 0.0im that changes the element type of NormalModeSolution.kr and of everything downstream of it.

Arguments

  • krs: the converged real wavenumbers.
  • modes: their normalized mode shapes, one per column.
  • env, props: the environment and the mesh the modes are sampled on.

Example

julia> env = UnderwaterEnv(pekeris_env(; αb=0.5)...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> cache = AcousticProblemCache(env, props);

julia> krs, modes = inverse_iteration(find_kr(env, props, cache), env, props, cache);

julia> eltype(krs), eltype(add_attenuation(krs, modes, env, props))
(Float64, ComplexF64)
source
Kraken.modal_attenuation — Function
modal_attenuation(ψ, kr, env::UnderwaterEnv, props::AcousticProblemProperties)

First-order perturbation δ(kᵣ²) of a mode's squared wavenumber due to material absorption.

ψ is a mode shape already normalized by normalize_mode. The perturbation formula assumes ∫ψ²/ρ + ψ(D)²/(2ρ_b γ) = 1, so passing an unnormalized eigenvector gives an answer wrong by that factor. kr is the real wavenumber the lossless solve converged to.

The result is purely imaginary and negative, so √(kᵣ² + δ) has a negative imaginary part and the mode decays with range. See the derivation in the comment block above; the units of env.α/env.αb are env.atten_units and are converted here, where the frequency is finally known.

Accuracy

Two independent limits, measured against kraken.exe and recorded in test/README.md. They hit opposite ends of the mode spectrum, so the affected modes tell you which one you are looking at.

  • The half-space term is first order in 2ω a_b/(c_b γ²), not in a_b. Since γ → 0 at the bottom cutoff, a strongly attenuating half-space degrades the least-trapped mode first: 10% for a near-cutoff mode over a 0.5 dB/λ seabed. The error comes from perturbation theory itself; only a full complex solve (krakenc.exe) removes it.
  • Everything else is ordinary discretization, at second order. The volume integral is taken medium by medium (see mode_energy and the note above it), so a jump in ρ or α at a layer interface is resolved exactly rather than averaged across by a straddling trapezoid. That is worth 27x on one_layer_env(; α1=0.4) (8.1e-2 against kraken.exe with one flat trapezoid, 2.9e-3 medium by medium), and it is what keeps a lossy sediment layer usable at the default mesh. Observed convergence order on that case: 2.00.

Calibrating against Fortran below about 1e-3 on a layered case measures kraken.exe's mesh rather than this one: its automatic mesh carries ~1.6e-3 of discretization error on one_layer_env.

Arguments

  • ψ: the normalized mode shape, on the flattened mesh.
  • kr: the mode's real wavenumber.
  • env, props: the environment and its mesh.

Example

julia> env = UnderwaterEnv(pekeris_env(; αb=0.5)...);

julia> props = AcousticProblemProperties(env, 100.0);

julia> cache = AcousticProblemCache(env, props);

julia> kr, ψ = inverse_iteration(first(find_kr(env, props, cache)), env, props, cache);

julia> δ = modal_attenuation(ψ, kr, env, props);

julia> real(δ) == 0 && imag(δ) < 0
true

Kraken.complex_soundspeed — Function
complex_soundspeed(c, α_nepers, ω)

KRAKEN's complex sound speed: c + i α c² / ω, for an attenuation α already in nepers per metre.

This is the last line of CRCI (alphaT = alphaT * c * c / omega; CRCI = CMPLX( c, alphaT )). The imaginary part is arranged so that ω / c̃ ≈ ω/c - iα, i.e. so a plane wave in a homogeneous medium loses α nepers per metre, as its units say.

Arguments

  • c: the real sound speed (m/s).
  • α_nepers: attenuation in nepers/m; convert with attenuation_nepers_per_m first.
  • ω: angular frequency (rad/s).

Example

julia> ω = 2π * 100;

julia> c̃ = complex_soundspeed(1500.0, 1e-3, ω);

julia> round(imag(ω / c̃); sigdigits=3)   # ≈ -α, to first order in α c / ω
-0.001
